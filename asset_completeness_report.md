# Asset completeness report - in-APK vs. CDN-only

Which of the game's asset paths can be recovered from
`input/app.apk`, and which exist only on the studio's CDN. Generated by
`python3 tools/asset-completeness-report.py` from
`source-app/game-assets/inventory.jsonl` (the bundle sweep's own
record) cross-referenced with the `gameres` path manifest. **Do not edit
by hand** - `python3 tools/asset-completeness-report.py --check`
regenerates it and fails if the file on disk differs.

## Sources

| Input | What it records |
|---|---|
| `source-app/game-assets/inventory.jsonl` | 30,293 rows: 7,868 bundle
| | names (every bundle shipped in the APK) and 22,425 object rows
| | (13,193 with a file written) |
| `decompiled/apktool/assets/AssetBundles/gameres` | the game's full
| | asset universe: 95,602 paths, 11,155 directories, 32,564 bundles, 46 groups

Of the 32,564 bundles the manifest describes, **7,868 are packed inside the
APK** (`BundleFragment0.bytes`) and **24,696 are not** - those are fetched
from `lastwar-cdn-*` on first run (`ConstURLConfig.cs`).

## Verdict

Every one of the 95,602 known asset paths falls into exactly one class:

| Class | Asset paths | Share | Meaning |
|---|---:|---:|---|
| Recovered from the APK | 11,741 | 12.3% | object in an APK bundle, file on disk |
| In-APK, content CDN-only | 5,078 | 5.3% | object in an APK bundle, payload (pixel/audio stream) empty there |
| In-APK, not exported | 18,877 | 19.7% | in an APK bundle, but no exported object resolved to the path |
| In-APK, decode failed | 3 | 0.0% | object in an APK bundle that the sweep could not decode |
| **CDN-only** | **59,903** | **62.7%** | every bundle carrying the path is absent from the APK |
| **In-APK total** | **35,699** | **37.3%** | present in an APK bundle in some form |

So of 95,602 asset paths the game knows about, 35,699 are reachable from the
APK (37.3%) and 59,903 (62.7%) are not - the recovered asset set is complete
with respect to the APK and necessarily partial with respect to the
game. Byte-wise the same split: 522,139,911 of bundle payload ships in the APK
vs 2,115,773,896 served from the CDN.

(`not exported` is mostly object types the sweep does not write - the
exported ones are Texture2D, Sprite, AudioClip, TextAsset - plus objects whose
name never resolved to a manifest path at all.)

The sweep wrote **11,795 files** (13,193 write rows; 1,030 output paths were
written more than once, from bundles that duplicate them). They cover
**11,741 recovered paths**, plus 53 files under `assets/_unresolved/`
whose objects carry no manifest path, plus 1 path that produced more
than one file - which is exactly where the files-vs-paths difference
goes.

The 9,232 rows without a file are the boundary in one number: 9,229 of
them are `no pixel data in this bundle` - Texture2D objects that ship
in the APK with an empty pixel stream, whose full-resolution bytes come
from the CDN (they cover 8,049 distinct manifest paths). UnityPy does not
fail on those, it returns noise sized like real art, so the sweep
refuses to write them (see README, *What the sweep recovers*).

## Edge cases and data-quality notes

- **629 object rows carry no manifest path** (their name never resolved
  against `gameres`). 53 of them still produced files, under
  `assets/_unresolved/<bundle>/`; the rest are empty-stream textures
  recorded by name and path_id only. Full list in
  `edge_cases.objects_without_manifest_path` in the JSON.
- **3 decode failures**, all in-APK, listed in full:
  - `Assets/_Art/Models/Soldier/Tanke/gpuskin/A_soldier_tanke_texture.asset` (path_id 7346603224488006725, gameres_auto_assets__art_models_soldier_tanke_gpuskin.bundle): `decode failed: ValueError: bytes must be in range(0, 256)`
  - `Assets/_Art/Models/Vehicle/YunBingChe/gpuskin/A_vehicle_ybc_texture.asset` (path_id 1660661121677387418, gameres_auto_assets__art_models_vehicle_yunbingche_gpuskin.bundle): `decode failed: ValueError: bytes must be in range(0, 256)`
  - `Assets/Main/Sprites/UI/CommonRemindNoAtlas/mjc_S3_zhiye_pop_bg02.png` (path_id 6323557828052766532, gameres_main_dir_sprites_ui_commonremindnoatlas_5.bundle): `decode failed: ValueError: PPtr can't deref with m_PathID == 0!`
- **246 paths disagree between the two sources**: the sweep found the
  object inside an APK bundle, but the `gameres` manifest assigns the
  path to a bundle that is not in the APK. Inventory wins (the object
  is demonstrably local); the full list is
  `edge_cases.manifest_assignment_disagrees` in the JSON.
- **2971 paths carry a written file *and* an empty-stream texture**
  (flagged `content_stream_cdn_only` in the JSON): the sprite exported
  fine, the standalone texture for the same path did not.

## What CDN-only means here

The client ships with 7,868 bundles and downloads the rest on first run
from the hosts in `ConstURLConfig.cs` (`lastwar-cdn.akamaized.net`,
`cdn.lastwar.com`, ...). Nothing in this repository can materialise
those 24,696 bundles - they are not in the APK, and the previous
revision of the sweep proved that guessing their pixels is worse than
nothing: it wrote 5,281 noise PNGs that looked like real art.

## Regenerating and verifying

```bash
python3 tools/asset-completeness-report.py           # rewrite both reports
python3 tools/asset-completeness-report.py --check   # exit 1 if stale
```

`tools/ci-checks.sh` runs the `--check` whenever the pipeline inputs are
present, so a report that no longer matches its inputs fails the build.
